# Audit: 4 October 2026

## Scope and evidence

This audit covers the manager → administrator → investor → auditor workflow in the new workspace at `http://127.0.0.1:4173/`. Fresh screenshots are in `screenshots/audit-2026-10-04/`. The functional flow was exercised in the current local server and the page was checked at desktop and 390px mobile width.

1. Manager prepares a standard and enhanced disclosure. **Healthy.** The form names both rights tiers and makes the separate approval step explicit. `01-manager.jpg`.
2. Administrator reviews and publishes. **Healthy.** The queue shows both payloads side by side; the GP cannot approve. Publication creates two scoped receipts. `02-administrator-review.jpg`.
3. Standard investor requests against the stale opening valuation. **Healthy.** The server refuses the request with a visible alert and does not reserve units. `03-standard-stale-refusal.jpg`.
4. Enhanced investor sees the enhanced payload and policy reference. **Healthy.** The standard payload is not present in the enhanced view and the receipt exposes its hash and approver on demand. `04-enhanced-receipt.jpg`.
5. Manager records a forward valuation, then an investor makes a partial request. **Healthy.** The current valuation changes the eligibility state and the request reduces available units while stating that settlement is not performed. `05-current-valuation.jpg`, `06-units-reserved.jpg`.
6. Auditor opens the register and exports evidence. **Healthy.** The event order, valuation history, reservation and host-tampering caveat are visible. The download was verified. `07-auditor-evidence.jpg`.
7. Mobile investor view. **Healthy.** At 390px the page has no horizontal overflow and the role picker, request form, receipt and rule remain reachable. `08-mobile-investor.jpg`.

## Code and contract findings

- Fixed: GP self-approval was blocked in the local API and Daml reviewer choice.
- Fixed: LP projections are deep-cloned before returning, so a caller cannot mutate server state through a response object.
- Fixed: client-supplied request timestamps and historical `asOf` values are rejected; freshness uses server time and includes exactly the 30-day boundary.
- Fixed: stale and over-quantity requests are atomic and reserve only the requesting LP's units.
- Fixed: Daml disclosure drafts store recipient rights and policy references at preparation time, so a later position replacement does not silently change a pending disclosure.
- Remaining: the Daml Script runtime is not executed in this environment because the installed SDK's Daml Script service artifacts are corrupt or incomplete. The production DAR and test DAR compile and validate; runtime results must be generated with `scripts/test-daml.ps1` after a complete SDK install.
- Remaining: DevNet proof is not present until the shared participant credentials and five party IDs are supplied. The adapter and smoke path are implemented, but no live transaction is claimed.

## Accessibility limits

Keyboard focus was checked and remains visibly outlined. Form controls have labels and server errors use `role="alert"`. A full screen-reader and keyboard-only audit beyond the captured flow still needs a dedicated pass.
